# 数据管理、转换调度与导出使用说明

`library.py`构建记录目录树并定位已完成MCAP，`exports.py`提供原始记录下载和TAR流；`workflow.py`调度转换、续转、LeRobot/原生记录回放，并提供LeRobot导出。网页由`static/robot_storage.js`、`static/workflow.js`、`static/native.js`调用这些API。实际格式转换实现在`../conversion/`，实际LeRobot/原生回放入口在`../replay/`。

## 目录选择与记录发现

采集目录使用`./datacp record-dir`；MCAP数据管理目录使用`./datacp library --root /data/data`；转换/导出的LeRobot根目录使用`./datacp lerobot-dir /data/r2_datacp/datasets`。三者各有用途，回放区独立选择来源目录，不会随转换输出目录自动移动或复制数据。接口与设置分别保存在`config/workspace.json`、`library.json`、`workflow.json`等。

网页支持MCAP目录树、原生采集目录树及单条/多条勾选。当前网页的factory发现/导出和原生回放启动检查仍使用`record/-genie-bundle_data.pbdat`作为目录标记；实际转换及回放动作由原始逐话题文件读取，不把bundle值当作动作。若原生目录没有该标记，网页可能不列出或拒绝启动，可用[独立转换](../conversion/README.md)或[独立回放](../replay/README.md)支持的源路径。

## 启动转换与继续中断任务

在机器人终端：

```bash
cd /data/r2_datacp
./datacp convert --input-format factory --source-dir /data/record/任务A \
  --output-dir /data/r2_datacp/datasets --name 任务A_训练集 \
  --task '把物体放进盒子' --workers 2 --threads 2
./datacp convert-status
./datacp convert-stop
```

MCAP将`--input-format`改为`mcap`并指定MCAP路径；也可重复`--episode /绝对路径/某条记录`指定多条，和`--source-dir`二选一。网页参数含输入格式、源目录/勾选记录、输出根目录、数据集文件夹名称、任务描述、并行记录数和每条线程数。输出为`输出根目录/数据集文件夹名称`。

后台创建项目根`runtime/conversion_<编号>/`，保存`inputs.json`、`command.json`、`progress.json`、`result.json`、`worker.log`；单条来源对应一个输出episode，多条按输入顺序合并。格式、24维映射、MP4、时间和NULL策略见[转换模块说明](../conversion/README.md)，本调度层不另改数据规则。

中途停止或服务重启后，网页会显示已明确提交任务的进度和中断原因；点击对应数据集的“继续这条数据的转换”会用原任务输入、输出和参数加`--resume`启动。接口为`POST /api/conversion/resume`，请求`run_dir`和`dataset`必须与该数据集最近明确提交的任务匹配，不能用当前页面新选择的来源替代。服务重启只恢复任务记录显示，不自动开始续转。

## LeRobot与原生回放调度

只读读取：

```bash
./datacp datasets
./datacp inspect --dataset /data/r2_datacp/datasets/任务A_训练集 --episode 0
./datacp native-inspect --source /data/record/full_实际名称
```

显式执行动作及停止：

```bash
./datacp replay --dataset /data/r2_datacp/datasets/任务A_训练集 --episode 0
# 或：./datacp native-replay --source /data/record/full_实际名称
./datacp replay-status
./datacp replay-stop
```

`workflow.py`使用原`replay/replay.sh`，两类输入共用该任务状态和停止接口，日志在项目根`runtime/replay_<编号>/`。网页只列出正式已提交的episode，中断的临时输出不作为已完成episode。原始指令/NULL及独立限幅平滑副本的差别见[回放说明](../replay/README.md)及[副本说明](../replay/README_clamped_smooth.md)。

## 导出到当前电脑

CLI的`--output`属于运行该CLI的电脑；网页保存到当前访问网页的电脑。导出保留源字节和层级，不删除机器人源文件，不重新转换：

```bash
./datacp library --root /data/data
./datacp export-mcap --episode /data/data/任务A/episode_1_采集时间 --output /tmp/任务A_mcap.tar
./datacp export-native --root /data/record --episode /data/record/full_实际名称 --output /tmp/原生记录.tar
./datacp export-lerobot --dataset /data/r2_datacp/datasets/任务A_训练集 --output /tmp/任务A_lerobot.tar
```

MCAP支持重复`--episode`，导出原始MCAP和附属文件；原生记录导出整条目录；LeRobot导出完整数据集。使用尚不存在的输出文件名。网页在浏览器支持时选择本地目录逐文件保存，否则下载TAR；LeRobot还提供manifest/file/archive接口。旧`RobotStorage.queue_transfer`不是当前`LocalStorage`的数据导出入口。

## 删除已完成MCAP

网页“删除所选机器人数据”调用`POST /api/library/delete`，请求含`episode_paths`及`confirm:true`，会实际永久删除所选MCAP记录目录或旧版MCAP及附属JSON。进行中的采集/回放、正被转换使用的来源会被检查；不能只删除一条episode的内部文件。原生记录和LeRobot没有该删除接口。此说明仅列功能行为，整理说明不会执行任何删除。
