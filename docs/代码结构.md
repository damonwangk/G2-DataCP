# 代码结构与入口

项目根目录：机器人`/data/r2_datacp`；当前Mac副本`/Users/x-1w/Downloads/R2-本体底层数据读取/r2_datacp`。按功能查找见[功能使用索引](功能使用索引.md)，操作命令见[使用说明](../使用说明.md)。每个自有代码文件最前的注释给出角色与所属功能MD。

## 1. 采集与网页：`studio/`

`studio` 是整个网页/API 工作台，承担编排和 MCAP 工作流；并非只存前端。MCAP 回放、导出代码继续放在这里，和采集使用同一套 MCAP 解析、目录及配置。

| 文件 | 负责的功能 |
|---|---|
| `robot_recorder_agent.py` | 独立采集后台；订阅、选通道、开始/结束/下一条，在机器人本地写 MCAP |
| `native.py`、`schemas.pb` | 原生 Aorta 报文读取、Protobuf schema、三路相机与本体通道解析 |
| `record_filter.py`、`storage.py` | 原始消息写入策略、episode 存储、MCAP 文件读取与画面预览 |
| `local_storage.py`、`robot_storage.py` | 网页连接本机采集后台、读取采集状态；历史远程存储兼容逻辑 |
| `recordctl.py` | 不经过网页的采集后台 CLI，访问本机端口 18767 |
| `app.py` | 网页/API 主入口，协调采集、预览、姿态、回放和目录管理 |
| `static/index.html`、`static/style.css` | 页面结构与样式 |
| `static/app.js`、`static/selection.js` | 页面基础交互、通道/关节选择 |
| `static/workflow.js`、`static/native.js` | 转换、独立来源的 LeRobot/原生记录回放和统一导出界面 |
| `static/robot_storage.js` | 原始数据目录树、多选、导出和 MCAP 删除 |
| `robot_replay.py`、`sdk_worker.py` | MCAP原始控制指令的选轴/时间窗口、厂商SDK后台回放；共用`replay/`读取与原发送器 |
| `postures.py`、`pose_worker.py` | 当前姿态保存、差值检查、恢复与可撤销删除；双夹爪单独保存，不包含底盘 |
| `sdk_limits.py`、`config/joint_limits_source.json` | 关节/夹爪数值范围和前端黄/红提醒 |
| `control_diagnostics.py`、`control_session.py` | 只读控制占用检测、执行时 SDK 控制权交接 |
| `selection.py`、`frequency.py`、`data_contract.py` | 可选数据/关节目录、频率统计、原始字段说明 |
| `pipeline.py` | 旧版数据分析辅助模块；当前原始采集不调用它做对齐或核验 |
| `sdk-run.sh` | MCAP 回放/姿态 worker 的 SDK 运行环境 |
| `start.sh` | 启动网页服务进程；一般通过项目根目录 `start.sh` 启动 |

当前操作按功能分为[采集与预览](../studio/采集与预览使用说明.md)、[回放与姿态](../studio/回放与姿态使用说明.md)、[数据管理与转换调度](../studio/数据管理与转换调度使用说明.md)。[采集实现参考](reference/采集实现.md)保留历史背景。测试在`studio/tests/`，本机相机样例放在`studio/tests/fixtures/`，不属于采集episode。

## 2. 格式转换：`conversion/`

| 文件 | 负责的功能 |

当前入口与映射见 [转换模块说明](../conversion/README.md) 和 [PLATFORM_MCAP.md](../conversion/PLATFORM_MCAP.md)。原版文档在 `docs/archive/conversion/`；OpenPI 接入在 [reference/OPENPI.md](reference/OPENPI.md)。

## 3. LeRobot / 原生回放：`replay/`

| 文件 | 负责的功能 |
|---|---|
| `dataset_info.py` | 只读解析 LeRobot 元数据、episode 和首帧 |
| `native_episode.py`、`source_episode.py` | 原生full/MCAP指令事件与Header PTP读取；反馈仅用于诊断 |
| `trajectory.py` | 24维别名映射、原目标保持与诊断，不改写原目标 |
| `lerobot_replay.py` | 原LeRobot/full/MCAP共用的SDK发送循环、进度、执行结果与trace |
| `replay.sh` | 设置机器人 SDK 库与 Python 环境，再启动回放进程 |
| `replay_clamped_smooth.sh`、`lerobot_replay_clamped_smooth.py` | 独立副本入口和发送循环；不会自动替换原网页/CLI执行器 |
| `clamped_smooth_targets.py` | 新副本按当前配置限幅、逐轴限速，仅变换发送目标 |
| `validate_clamped_smooth_samples.py` | 两条真实full及对应LeRobot纯读取全轨迹验收 |
| `test_*.py` | 模拟 SDK 与离线数据测试 |

原网页由`studio/workflow.py`启动LeRobot/full进程，MCAP由`studio/robot_replay.py`和`sdk_worker.py`管理并复用这里的原执行器。读取文件不加载SDK，执行才加载。独立限幅平滑副本必须手动用自己的Shell入口启动，说明分别见[原回放](../replay/README.md)和[限幅平滑](../replay/README_clamped_smooth.md)。

## 4. 跨主机批转换与底盘

`batch_upload/`由robot主机的`start.sh`、`runner.py`、`progress.py`和桌面脚本管理每条full独立的数据集，配合`conversion/`运行；批任务说明（见部署系统原位置）区分local-only包装入口与直接runner的历史上传默认。它不由G2工作台服务管理，Mac保存完整源码不等于G2已部署所有工具。

`底盘控制/`在G2通过`run_chassis.sh`调用`g2_chassis.py`，`mapping.py`、`ab_no_map.py`、`ab_map.py`提供地图/A→B功能。默认预览，显式`--execute`才执行。旧Ubuntu启动器有独立worker路径，不能与当前`/data`副本混用。见底盘README（见部署系统原位置）。

## 5. 导出与删除

| 格式 | 文件索引/选择 | 导出实现 |
|---|---|---|
| MCAP | `studio/library.py` | `studio/exports.py`；保存原始 MCAP 和附属文件 |
| 原生 pbdat + H.265 | `studio/library.py` 的 factory 目录树 | `studio/exports.py`；保存原生记录完整目录 |
| LeRobot | `studio/workflow.py` 的数据集目录 | 同文件的 manifest / file / archive 接口；导出完整数据集 |

`datacp` 使用这些同一 API 下载文件。网页的本地目录写入与 TAR 下载由 `static/robot_storage.js`、`static/workflow.js` 调用；不会重新转换数据。现有 MCAP 删除接口在 `studio/app.py`、`studio/library.py`。

## 6. 运行环境和数据不混入代码

- `studio/_deps/`：网页、MCAP 和 Protobuf 的机器人本机依赖。
- `conversion/.venv/`、`conversion/extra_deps/`：机器人 Python / LeRobot 环境。
- `conversion/wheelhouse/`、`conversion/vendor/`、`studio/vendor/`：离线安装材料，保留以便机器人无外网时使用。
- 厂商 SDK 在机器人 `/home/agi/app`；项目不重复拷贝一套 SDK。
- `studio/config/`：实际设备配置及目录偏好；其中设备专属文件不公开同步到 GitHub。
- `runtime/`、`studio/runtime/`：执行日志；`datasets/`：训练数据；`studio/poses/`：姿态。
- `data/raw/`：历史保留数据。当前 MCAP 主保存目录通过采集设置读取，通常为 `/data/data`。
- `deployment/`：保留当前功能验收和本次文件整理清单；旧开发备份、日志和缓存已清理。

系统服务仍引用原来的路径，文件整理不更改 SDK、配置、数据和依赖位置。`r2-mcap-recorder.service` 运行采集后台，`r2-mcap-studio.service` 运行网页/API；均手动启动。
