# 平台启动、关闭与统一命令行

本功能由根目录`start.sh`、`stop.sh`、`datacp`和`studio`内服务共同完成。`datacp`本身是只用Python标准库的HTTP客户端；它不会安装或启动服务。各模块的输入输出和详细命令见[功能使用索引](功能使用索引.md)及[总使用说明](../使用说明.md)。

## 在G2手动启动与关闭

```bash
cd /data/r2_datacp
./start.sh
./datacp status
```

前提是`r2-mcap-recorder.service`与`r2-mcap-studio.service`两个systemd用户服务已安装，且路径指向本项目。启动只启动采集后台和网页/API，不自动开始录制、回放或姿态恢复，不设置开机自启。网页监听18769，采集代理监听18767。电脑访问`http://机器人IP:18769/`，网线入口为`http://10.42.1.101:18769/`，无线地址以当前网络和脚本输出为准。

停止整套平台：

```bash
./stop.sh
```

会结束平台管理的转换/回放进程，并让采集后台完成MCAP写入。只关闭浏览器不会停止后台。根启动/停止脚本不管理独立终端的限幅平滑副本，也不管理robot主机独立运行的批转换任务。

服务状态与日志：

```bash
systemctl --user status r2-mcap-recorder.service r2-mcap-studio.service --no-pager
journalctl --user -u r2-mcap-recorder.service -n 50 --no-pager
journalctl --user -u r2-mcap-studio.service -n 50 --no-pager
```

`studio/start.sh`、`studio/open-workbench.sh`是内部服务/兼容访问入口，日常使用根目录启动脚本；不应为查看说明再启动第二份服务。

## CLI使用方式

```bash
./datacp --help
./datacp convert --help
./datacp replay --help
./datacp --url http://机器人IP:18769 status
```

语法为`./datacp [--url 地址] 子命令 [参数]`；`--url`必须放在子命令之前，默认来自`DATACP_URL`或`http://127.0.0.1:18769`。`--help`只解析参数，不连接API；状态查询需要网络和已有服务。结果为JSON，HTTP错误和本地异常写入标准错误。

| 功能 | 子命令 | 详细说明 |
|---|---|---|
| 采集目录、录制、下一条、停止 | `record-dir`、`record-start`、`record-next`、`record-stop`、`record-status` | [采集与预览](../studio/采集与预览使用说明.md) |
| 转换及LeRobot输出根目录 | `lerobot-dir`、`convert`、`convert-status`、`convert-stop` | [转换](../conversion/README.md)、[调度](../studio/数据管理与转换调度使用说明.md) |
| 数据目录与元信息 | `library`、`mcap-files`、`datasets`、`inspect`、`native-inspect` | [数据管理](../studio/数据管理与转换调度使用说明.md) |
| 原回放 | `mcap-replay`、`replay`、`native-replay`及对应status/stop | [原回放](../replay/README.md) |
| 完整原文件导出 | `export-mcap`、`export-native`、`export-lerobot` | [总说明第7节](../使用说明.md#7-导出到机器人本机mac-或其他电脑) |

`record-start/record-next`会写采集文件；三个回放启动命令会发送动作。查询、转换和导出不等于动作回放。独立限幅平滑副本使用`replay/replay_clamped_smooth.sh`，没有接入这些CLI回放命令。

## 在Mac访问同一服务

```bash
cd /Users/x-1w/Downloads/R2-本体底层数据读取/r2_datacp
python3 datacp --url http://机器人IP:18769 status
```

Mac只需Python 3和网络，不需要GDK或复制Linux虚拟环境。传给服务器的源路径是机器人路径；`export-* --output`是运行客户端的电脑上的新TAR文件名。若使用SSH转发，`127.0.0.1`及端口应与实际转发一致。

## 文件职责与离线检查

`start.sh/stop.sh`调用systemd；`datacp`把命令翻译为HTTP请求；`studio/app.py`提供API；`studio/robot_recorder_agent.py`提供采集后台；`tests/test_datacp.py`使用Mock验证参数与HTTP契约。离线测试：

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

这些测试不要求服务启动，不接触真实SDK或采集任务。安装状态、网络连通和真实运动结果均须由当前现场状态另行确认。
